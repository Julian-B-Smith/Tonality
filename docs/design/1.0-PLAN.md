## What 1.0 means

1.0 is the **stability line**: Tonality's first human-cut release tag.
- **Before it,** every surface may change.
- **After it,** *stable* surfaces change only under semver. A fix may change
  output only where the output contradicted a recorded contract, and the golden
  diff for it is reviewed and listed.

1.0 does not mean "feature-complete". It means the engine's reason to exist is
complete and its contracts are frozen: exact identity arithmetic, honest ranked
context, and reproducible datasets.

## Stability tiers: how 1.0 ships everything without promising everything

Every tool and public function declares one tier, carried in the tool manifest:

| Tier | Meaning in 1.x |
|---|---|
| **stable** | Name, parameters, defaults and result JSON are frozen. Additive optional parameters and additive result fields are allowed. |
| **provisional** | It may change in a MINOR release, with a changelog entry. |
| **experimental** | It may change at any time and is labelled as such in its description. |

**Proposed assignment (for Julian to ratify):**
- **Stable:**
  - identity and catalogue;
  - key induction, tie-breaker, tracking and structural areas;
  - cadence detection; global meter estimation;
  - the melodic, rhythmic and voice atoms and the atom vocabulary;
  - patterns;
  - the ruleset DSL (validate, evaluate, combine, specialize, diff, manifest,
    libraries);
  - inverse identity search;
  - voicing enumeration with a required window;
  - conform, remap and retonicize;
  - the modal transform;
  - the keyboard, bracelet, Tonnetz, piano-roll and colour-content descriptors;
  - the MIDI → dataset pipeline, MIDI export, and the versioned-data export;
  - the HTTP bridge.
- **Provisional:**
  - local meter tracking;
  - chromatic-event classification;
  - swing, percussion, coalescing and part relations;
  - melodic tendency;
  - next-chord recommendation (the axes and evidence tags are stable; the
    ranking is a prior);
  - voicing suggestions;
  - the chord network;
  - tonal orientation.
- **Experimental:**
  - rule induction;
  - statistical style (transition matrices, cross-entropy, style profile);
  - ruleset repair;
  - groove apply.

## What 1.0 does not promise

- **Cut from 1.0, recorded for after it:**
  - the transformation-recommendation surface (gap 32), which needs a frozen
    plan first;
  - walk preservation under forced collapse (gap 31c);
  - `TransitionIdentity` (gap 30);
  - plural chord hearing (gap 22);
  - incremental and streaming APIs (gap 5);
  - live MIDI input (gap 4, descoped);
  - beyond-12-TET identity (Phase 6).
- **Specific numbers are not promised.** Accuracy figures are Layer-E,
  measured and never guaranteed. The *meaning* of a margin is frozen per prior
  version; its values are not frozen across versions.

## Where this departs from the clean-room answer

- **The HTTP bridge is stable, not provisional.** The clean-room agent called it
  "a convenience transport". In reality it is Audiology's lifeline door, and
  ROADMAP already treats bridge stability as a GUI-availability concern.
- **The MCP SDK 2.x port is a MUST.** The agent could not know the endpoint is
  pinned below the current SDK major. Freezing 1.0 on a deprecated major would
  freeze a ceiling.
- **Determinism is promised on Linux and macOS, not Windows.** No current
  consumer runs the Python engine on Windows. Windows is NICE until one does.
- **No `Fraction` beats for 1.0.** The agent's exact-time representation would
  dissolve the fragmented-tolerance debt (ROADMAP RE-7c), but it touches every
  temporal module and golden. That is a 2.0-sized change; 1.0 names the
  tolerances instead.
- **Performance numbers are left blank until measured.** The agent's budgets
  (≤ 50 µs per identity call, ≤ 2 s per three-minute MIDI file) are its own
  guesses. The perf part's first act is to measure, then propose numbers for
  Julian to set.

## The release gate (all blocking at 1.0)

- [ ] Layer 0 is green on the OS × Python matrix, including the hash-seed sweep.
- [ ] Every stable tool has at least one acceptance fixture through both the Python and tool doors.
- [ ] The API, manifest, schema and prior locks are committed, and the bump checker passes.
- [ ] Every must-fail guard passes, the fuzz run shows zero 500-class results, and the scan is clean.
- [ ] The performance ceilings hold.
- [ ] The conformance corpus is regenerated and the port pin is current.
- [ ] The plan gates (promises 12–14) pass.
- [ ] The docs build is clean and the changelog has an entry for 1.0.
